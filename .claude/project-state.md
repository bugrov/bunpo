## Решения по прохождению тем и повторениям (для шагов 5-6, решения пользователя)
**Согласовано**
- Все темы открыты, замков нет (свободный режим). Зависимости `prerequisites` из перечня служат мягкой подсказкой («рекомендуется сначала: …»). Кнопки «открыть всё равно» и «я это знаю» не нужны, пропуска нет: пройти тему можно только через урок и тест.
- Состояния темы: новая → в процессе (урок начат или набрано меньше порога) → пройдена. Поверх: «пора повторять» (из FSRS, не хранится отдельно) и «слабая» (много ошибок на повторениях).
- Порог «пройдена»: ≥75% правильных ответов с первой попытки в мини-тесте (5 упражнений из пула). Неверные ответы возвращаются в конец для закрепления, но в процент не идут. Ниже порога: тема остаётся «в процессе», урок дня предлагает её снова. Независимо от порога результат урока идёт в FSRS по обычной таблице (без ошибок Good, 1 ошибка Hard, 2 и больше Again). «Пройдена» (прогресс) и «в повторениях» (память) это два независимых механизма.
- Пул упражнений темы должен быть не меньше 6-8 (для повторных прохождений и повторений); при работе над шагом 4 поднять минимум в схеме с 4 до 6 (правка схемы и тестов).
- «Урок дня» берёт первую непройденную тему по порядку перечня; в каталоге можно выбрать любую. Прогресс по разделам («N5: 14 из 120»).
- Повторения: отдельная страница (именованный роут `review`), на «Сегодня» сводка и кнопка входа. Сессия идёт по темам с наступившим сроком FSRS, по одному упражнению из пула, теория скрыта (кнопка «Посмотреть правило»), дневной лимит повторений. Режим «Освежить» без влияния на расписание не в v1.

## Рендеринг, кэш и защита роутов (решения пользователя, реализация в шагах 3 и 6)
- **Режимы рендера:** вся зона внутри приложения (каталог с прогрессом, страницы тем, урок, повторения, прогресс, настройки) это SPA (`ssr: false`). SSG только лендинг (вероятно `ssr: false` на всём приложении и `routeRules: { '/': { prerender: true } }`; точную комбинацию проверить по документации при настройке). ISR не нужен: контент меняется только деплоем. В HTML нет персональных данных.
- **Получение данных:** `useFetch`/`useAsyncData` с явными ключами (`grammar:<id>`, `progress:<id>`), действия пользователя через `$fetch`. Ключ даёт дедупликацию и общее состояние, но не постоянный кэш в SPA (getCachedData по умолчанию только при гидрации). Два запроса параллельно: `await Promise.all([...])` (два подряд `await` дают водопад) или `lazy: true` для личной части. После урока `refreshNuxtData('progress:<id>')`.
- **Фуригана:** вместо `v-if` в `UiRuby` переключать видимость CSS-ом (`html[data-furigana=off] rt { display: none }`), атрибут выставлять скриптом из localStorage до отрисовки (позже из настроек в БД). Правка `UiRuby`/`useFurigana` в шаге с уроком или каталогом.
- **Кэш публичного контента:** `defineCachedEventHandler` (Nitro 2.13.5) на `/api/grammar/:id` и `/api/curriculum`: `maxAge` порядка часа, swr; заголовки etag, last-modified и `cache-control: s-maxage, stale-while-revalidate` Nitro ставит сам; хранилище по умолчанию память инстанса; в dev кэш отключён (`shouldBypassCache: () => import.meta.dev`). **Кэшируемые обработчики не читают сессию и куки** (в Nitro v2 куки запроса не вырезаются и не входят в ключ). Личные API без кэша.
- **Защита роутов:** клиентский глобальный middleware `auth.global.ts` по принципу «закрыто по умолчанию»: страница открыта только если `definePageMeta({ public: true })` (лендинг, вход, регистрация); редирект на `ROUTE.login`. `guest.ts` для входа и регистрации (залогиненных отправляет на «Сегодня»). Поле `public` добавить в `PageMeta` через `declare module` в `app/types/index.ts`. Редирект после входа всегда на «Сегодня» по имени роута (адрес из query не принимаем). Макеты: `layouts/app.vue` для защищённой зоны.
- **Сервер:** `requireUserSession(event)` в каждом защищённом эндпоинте плюс фильтр по `session.user.id`. Тест обходит `server/api` и проверяет: эндпоинт в явном списке публичных/кэшируемых (grammar, curriculum, вход, регистрация) либо без сессии отвечает 401.
- **К проверке по документации при реализации:** готовность сессии в SPA до первой навигации (`useUserSession().ready`), комбинация `ssr: false` и prerender лендинга.

Запасной хэш для неизвестной почты ждётся всегда (выравнивание времени первого запроса). У Pool есть обработчик `error`. - `Ui*` собраны на нативных элементах с BEM (без обёрток над shadcn), чтобы не дублировать стили. shadcn-vue подключаем позже для сложных компонентов (dialog, select, tabs). Для этого `components.json` уже указывает `ui` → `@/components/ui/shadcn`.
- Модуль `shadcn-nuxt` и пакет убраны из зависимостей до первого shadcn-компонента (иначе предупреждение про отсутствующую папку). Вернуть вместе с `shadcn: { componentDir: './app/components/ui/shadcn' }`.
- Иконки: Lucide (`iconLibrary` в `components.json`), пакет пока не установлен; сделаем обёртку `UiIcon`, когда понадобится первая иконка.
- `ROUTE` лежит в `shared/routes.ts` (не в `shared/utils`), поэтому не автоимпортируется: импорт `#shared/routes`.

## Замечания
- TypeScript закреплён на `~6.0`: typescript-eslint не поддерживает TS 7.
- FSD-правило ESLint ловит только явные импорты, автоимпортируемые компоненты не видит: проверять на ревью.
- `/styleguide` существует только в dev: `config/devPages.ts` (`removeDevOnlyPages`) подключён хуком `pages:extend` в `$production`. Проверено production-сборкой: `/` отдаёт 200, `/styleguide` 404.
- `tests/unit/ruleset.test.ts` поднимает ESLint (около 3 секунд), это нормально.
